# Tracking monitor redesign — local verification

Recorded 2026-10-19 (Asia/Dhaka), covering work and evidence captured on 18–19 October.
Branch: `codex/tracking-monitor-redesign`. Owner approval: implement the full plan, with the six decisions in
[design §11](../plans/tracking-monitor-redesign-plan.md#11-owner-decisions--resolved-2026-10-18).

## Implemented

- Programme Monitor is the landing view; Manage retains the existing editing tools and retrospective link.
- Code dashboards expose receipts over time, lifecycle/rules, offices, item prices, private documents and contacts.
- Office views support all-programme, programme and code levels, scope explanations, comparisons, monthly receipts,
  per-item quantities and an independently authorized inventory panel. The directory uses the office scope and only
  counts separately authorized programmes. `tracking.office_directory_enabled` defaults to true after the checks;
  `TRACKING_OFFICE_DIRECTORY_ENABLED=false` remains the kill switch for both routes and navigation.
- Metrics use active associations, cap each matrix cell, average target fulfilment, and exclude drafts from live
  aggregates. Missing receipt metadata remains unknown. Prices use a neutral weighted average/min/max/spread.
- Eight reusable theme patterns, Lab examples, semantic statuses and English/Bangla keys are included. Charts use
  theme tokens and accessible data tables. New read routes perform no business-data writes.
- Every tracking web/API route declares one named `gov.can:` ability, alongside existing programme/object/state
  checks. MONITOR is read-only, including labelled draft reads. Native admin remains distinct from superuser.
- Global funding settings use the existing national review/reason/confirmation/expiry/replay workflow, with a
  fingerprint of the affected funding rows and linked-code count. Rendered mutation failures retain their failure
  audit and roll back the mutation.
- Activation provenance and durable receipt-line/movement/snapshot linkage are added. Posting passes its exact
  receipt item into the existing event. New receipts retain the replay guard. Historical source recovery only uses
  a unique proved link; the targeted fact-rebuild command refuses incomplete repairs.

Runtime changes stay in GovStore packages. The existing unrelated Store Operations JavaScript changes were not
edited or included in the redesign commits. No Snipe-IT core or root PHPUnit configuration change was made.
