Asset tagging সম্পদ ট্যাগিং

Every unit received through a GRN gets one permanent tag. The Finance Code is optional: without it, the unit gets a standard tag.

Demonstration values. Office codes are fictional until each office enters its own.

Standard tag

native sequence
GS-004217 Installation prefix + next number

Issued for every other unit in an enabled office:

  • no Finance Code on the product type or the line
  • Finance Code present, but no challan or PO date and the storekeeper chose to keep standard tags
  • donation, transfer-in or opening-balance receipts (until decision D-04)

Both kinds are permanent. Neither is ever regenerated or reused.

How a unit's tag is chosen at posting

  1. 1Is the office enabled? If not, nothing changes, except that typed tags shaped like Govt. Tags are rejected.
  2. 2Does the line have a Finance Code? Inherited from the product type, or chosen for this line. If not, a warning offers a fix; otherwise the unit gets a standard tag.
  3. 3Purchase receipt with a Supplier Challan or Purchase Order date? If not, the GRN shows Needs attention: fill the existing date, or keep standard tags for that line.
  4. 4Govt. Tag issued. The sequence is reserved inside the posting transaction and printed afterwards.

Design principles

Plain words first"Govt. Tag" and "Standard tag". Codes always sit beside names.
Optional means optionalA missing Finance Code never blocks anything. The consequence is shown instead.
Show it before it happensThe live preview and posting summary show exactly what will be issued.
Say "permanent" once, clearlyOne honest sentence at posting. Typed confirmation is kept for national changes.
Name the ownerRead-only values say who sets them and how to ask for a change.
Show the least data neededA tag never grants access. Lookup answers "missing" and "forbidden" the same way.
