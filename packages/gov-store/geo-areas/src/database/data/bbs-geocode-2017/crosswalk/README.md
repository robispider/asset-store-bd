# GovStore geo_areas ↔ BBS geocode (June 2017) crosswalk

Generated by `tools/crosswalk_bbs_geocode_2017.py`. Linked **8,583 of 9,111** current areas; **528** are unmatched. **438 of 9,016** BBS admin areas have no current counterpart.

This is match coverage under the rules below, not measured accuracy. The BBS volumes are dated June 2017, so areas created or renamed later legitimately appear as unmatched on one side.

## Files

- `matched.csv` — current rows (nine original fields unchanged) with the linked BBS codes, names and `match_method`.
- `govstore_unmatched.csv` — current rows without a link, with `reason` and up to three review candidates.
- `bbs_unmatched.csv` — BBS zila/city/upazila-thana/paurashava/union-ward rows not linked to any current row.
- `summary.json` — counts and input hashes.

Review candidates are spelling similarity only and are never assignments. Import BBS codes as text to keep leading zeros.

## Matching tiers

Inside an already matched parent, a link needs a key that is unique on both sides:

0. `reviewed` — explicit links in `REVIEWED_LINKS` for upazilas renamed or re-spelled since 2017 (e.g. Zianagar → Indurkani); each carries its reason in `notes`.
1. `exact` — normalized English name (case, spaces, punctuation and type suffixes removed; ward numbers normalized).
2. `alias` — reviewed spelling aliases (Chittagong/Chattogram, Comilla/Cumilla, Barisal/Barishal, Jessore/Jashore, Bogra/Bogura and a few district spellings), parenthetical alternatives for upazila/thana names, current `Sadar` = matched district name + SADAR, serial prefixes (`7no Sofapur`), ward number only, and direction words in any position (north/uttar, south/dakshin/dakkhin, east/purba, west/pashchim). The `bangla` and `skeleton` keys use the same direction rule.
3. `bangla` — the repaired BBS Bangla name equals the current Bangla name. The repair is best-effort, so this tier only ever confirms exact equality.
4. `skeleton` — English consonant skeleton (vowels, h/w/y removed; z→j, v→b, ph→f). Weakest tier: review or exclude it if you need strict links. Children of a skeleton match are matched normally.
5. `ward_set` — city thanas only. Some volumes (Dhaka) never name their metropolitan thanas; the thana code appears only on ward rows, so `bbs_en_name` is blank. A thana is linked when its ward numbers and the BBS thana's ward numbers are each other's unique best overlap (Jaccard ≥ 0.5).

City thanas are matched against BBS thanas listed under the city and against upazila/thana rows referenced by that city's wards. One BBS area can be linked from two current types (e.g. a Sadar upazila and the city thana of the same code); `notes` names the other row.
